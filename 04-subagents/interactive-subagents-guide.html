Subagents (子代理) 蜂巢架構與派工教學台

上下文隔離 (Context Isolation) ‧ 工具權限白名單 ‧ 平行專家分工

課堂情境演練：
💡 教學心法：主包工程師與專業工班模型 學生秒懂的核心概念

告訴學生：主代理 (Main Agent) 就像工地的總工程師，負責掌握全域架構與最終決策。他不需要親自讀 50 個檔案來做 Review，而是派遣「專屬子代理 (Subagent)」在獨立封閉的工作間裡施工。 子代理只攜帶被允許的工具 (tools 白名單)，做完只交回精簡驗收報告，確保總工程師的辦公桌 (Context 記憶體) 永遠乾淨清爽！

🧠 上下文視窗負載 (Context Budget)

Subagent 模式
主代理 (Main Context) 8,420 / 200,000 Tokens (4%)

主記憶體維持清爽，完全沒有雜亂的中間輸出！

子代理獨立沙盒 (Isolated Sandbox) 48,900 Tokens (沙盒內消耗，結束即銷毀)

✨ 驚人優勢：這 4.8 萬個 token 的中間雜訊被安全隔離，不會污染主對話！

🎯 教學重點：如果把審查 30 個檔案、執行百次 grep 的髒活都讓主 Agent 做，主對話會立刻爆衝到 15 萬 tokens，導致 AI 出現遺忘與幻覺。用 Subagent 就能零負擔回收精華結果！

使用者對 Claude 說：『請幫我審查專案所有的程式碼是否符合 Clean Code，並且撰寫測試驗證！』現在讓我們來看看派工流程。

1. 主代理派工指令 (Delegation)

Main → Subagent

主代理使用 Task 工具產出子代理，並指定專用提示詞：

// 主代理自動調用 Task 工具：
Task(
  subagent_type: "clean-code-reviewer",
  task_prompt: "審查最近新增的 3 個模組，特別針對函式行數、命名原則與例外處理，產出 Critical/High 等級報告。"
)
💡 主代理指派任務後，即刻切換為「等待回報」狀態，不會參與中間的每一步細節。

2. 子代理設定檔 (Markdown)

clean-code-reviewer.md

位於 .claude/agents/ 目錄下的專用角色規範：

---
name: clean-code-reviewer
description: Clean Code 原則落實專家。
tools: Read, Grep, Glob, Bash
model: inherit
---

# Clean Code 審查代理
你是一位資深程式碼審查員，專精於 Clean Code 原則。
- 函式少於 20 行
- 單一職責原則 (SRP)
- 絕不使用魔術數字
- 發現違規時，附上檔案路徑與行號！
🔒 權限隔離亮點：沒有給予 Edit 或 Write 工具，保證子代理只看不改！

3. 驗收回傳報告 (Clean Report)

Subagent → Main

子代理在沙盒跑完 50,000 tokens 後，只回傳精華重點：

# Clean Code 審查報告完成

【違規項目發現】
1. src/auth/token.ts:42
   - 級別：High
   - 問題：函式超過 58 行且承擔過多職責。
   - 建議：將 JWT 驗證與資料庫查詢解耦。

2. src/api/user.ts:15
   - 級別：Medium
   - 問題：使用魔術數字 86400000。
   - 建議：提取為常數 TOKEN_EXPIRATION_MS。
🎉 大功告成：主代理吸收這份 300 字報告，直接向使用者回報或開始精準重構！

🛡️ 1. 安全與唯讀審查員

限制工具為 Read, Grep，負責掃描密碼外洩、SQL Injection 或資安弱點。即使 AI 幻覺也不可能改動任何現有程式碼。

🧪 2. 測試與驗證工程師

在獨立沙盒中執行 pytest 或 npm test，產生上千行測試輸出也不會塞爆主代理的上下文記憶體！

⚡ 3. 平行分工 (Parallel Execution)

主代理可同時派發「前端審查」與「後端測試」，兩位子代理在各自的沙盒同時奔跑，節省 50% 以上的等待時間。
