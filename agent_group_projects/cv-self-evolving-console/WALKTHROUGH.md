# 用 AI 蓋一台「會自己學」的 CV 主控台 Walkthrough

> **對象**：AI 訓練有點概念但不熟的人。會開終端機就行，不會寫 Python 也沒關係
> **形式**：自己照著做 / 講師現場帶
> **時長**：Phase 0–2 約 50 分鐘（跑起來 + 看懂 + 故意弄壞）；Phase 3 再 30 分鐘（看它是怎麼被蓋出來的）
> **產出**：你電腦上會有一台真的跑得動的畫面，而且你會知道「怎麼指揮 AI 蓋一個不會騙你的系統」
> **核心方法**：**不要相信 AI 的第一個答案，也不要相信它說「我做好了」。讓它自己證明給你看。**

> 💡 **下面會出現一些專有名詞。看不懂就往下滑到「[名詞對照表](#-名詞對照表看不懂就回來查)」，那裡每個都用白話解釋過。**

## ⚠️ 先講清楚：現在按下去會發生什麼

很多人看到畫面上有「開始訓練」「epochs」「mAP」就以為按下去只是動畫。**現在是真的。**

| 你以為 | 實際上（現在這個版本） |
|---|---|
| 按下去會訓練一個 AI 模型 | ✅ 會。yolov8n · 10 epoch · 跑在 MPS 上 |
| 會用 GPU | ✅ 會（Apple Silicon 的 MPS） |
| 要 Roboflow 帳號 / API key | ❌ 不用 |
| 要連網路 | 只有「LLM 命名」那一步要 |
| 會花錢 | ✅ 一次 `claude -p`，實測 **$0.25–0.41**（整輪上限 $0.5） |

**現在按下去實際做的是一整條龍（s01 → s08）**：

1. 產生 120 張假的晶圓照片，**一張一張**送到畫面上（s01）
2. 用**純幾何方法**自動在每張圖上畫框（s03，不是 AI，是數學）
3. KMeans 分群 + **一次 LLM 命名**六個群（s02）
4. 凍結 class 真相表、切 train/valid、封印 test（s04）
5. 探針選模型（s05）→ 凍結配方並**真的訓練**（s06+s07）
6. 評分：noise floor、bootstrap CI、四項 check、裁決 + 四張圖表（s08）

畫面最上方 11 格流程燈，**s01–s08 八格都會亮**，s09–s11 是灰的（討論與自我進化，M6/M7）。

> ⚠️ 亮的順序不是 1→2→3：**s03 會比 s02 先亮**。這不是壞掉 —— 要先有框，才分得了群。

> **教學金句**：「一個誠實的半成品，會把還沒做的部分顯示成灰色；一個不誠實的半成品，會放一根假的進度條讓你以為它在跑。」

這份教材要教你的，剛好就是**怎麼讓 AI 蓋出前者而不是後者**。

## 📖 名詞對照表（看不懂就回來查）

### 這個專案在幹嘛

| 名詞 | 白話 |
|---|---|
| **CV** | computer vision，電腦視覺。**讓電腦看照片、找出照片裡有什麼**。這個專案是看晶圓照片找瑕疵 |
| **晶圓（wafer）** | 做晶片的圓形矽片。上面有瑕疵就要挑出來 |
| **bbox** | bounding box，**框住東西的那個方框** |
| **GT** | ground truth，**正確答案**。這裡是程式自己畫圖時就知道的那 155 個框 |
| **labeling / 標註** | 人工在照片上畫框並寫下「這是刮痕」。傳統做法要人一張一張畫，很貴 |
| **連通分量** | 「把黏在一起的黑點當成同一個東西」的數學方法。**這就是這版自動畫框的原理** |
| **IoU** | 兩個框重疊的程度，0～1。**1 代表兩個框完全一樣** |

### 電腦名詞

| 名詞 | 白話 |
|---|---|
| **前端** | 你在瀏覽器**看到、能點**的那個畫面 |
| **後端** | 在你電腦背景跑、負責算東西的程式（Step 0.5 跑起來那個） |
| **API** | 前端跟後端講話的**固定格式**，像餐廳的點餐單 |
| **SSE** | 伺服器「一直講、你一直聽」的技術。所以照片能一張一張跳出來 |
| **assert** | **考卷上的一道題**。程式自己檢查「這件事是不是真的」，不是就變紅（FAIL） |
| **M0 / M1 / M2…** | **里程碑編號**，就是「做到第幾階段」。**你手上這版是 M1：只產圖 + 自動畫框，不訓練** |

### AI 訓練名詞

| 名詞 | 白話 |
|---|---|
| **PyTorch** | 訓練 AI 用的工具箱（像遊戲引擎）。**這版沒裝**，M3 才會裝 |
| **GPU** | 顯示卡。訓練 AI 要靠它算才快。**這版完全不用** |
| **LLM** | 大型語言模型，就是 ChatGPT / Claude 那種會講話的 AI |
| **epoch** | 把所有考古題唸過一輪叫一個 epoch |
| **mAP** | 模型考試的分數，越高越好（滿分 1.0） |
| **agent / subagent** | 你請 AI 扮演的一個專門角色，例如「只負責資料的那位」 |

### train / valid / test 的比喻（整個專案最重要的觀念）

| | 比喻 | 可以看幾次 |
|---|---|---|
| **train** | 考古題 | 無限次，就是拿來練的 |
| **valid** | 模擬考 | 每次練完考一下，看有沒有進步 |
| **test** | 正式考 | **整個學期只能考一次** |

如果你「先偷看正式考的題目，再回去調整唸書方法」，那你考 100 分也不代表你真的會。

**這是 AI 訓練最常見、最致命的作弊方式，而且常常是不小心的。** 這個專案花了很大力氣在程式碼層面讓這件事**做不到**（不是靠「我們約好不要這樣」）。

> **教學金句**：「正式考只能考一次。你如果改了四次唸書方法、考了四次正式考，那第四次的分數是假的。」

## Phase 0：先跑起來（15 分鐘）🛠

**你不需要看懂任何程式碼。目標只有一個：看到畫面動起來。**

### Step 0.1：裝 uv 和 Node.js

**uv**（裝 Python 套件用）：

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

⚠️ **裝完要關掉終端機重開**（或跑 `source $HOME/.local/bin/env`），不然找不到指令。然後確認：

```bash
uv --version
```

看到 `uv 0.x.x` 這種版本號才算成功。看到 `command not found` 就是終端機沒重開。

**Node.js**（考卷第 B 題要用）：

```bash
brew install node     # 沒有 brew 就去 https://nodejs.org 下載安裝檔
node --version
```

💡 **為什麼考卷需要 Node.js？** 因為第 B 題要**真的把前端那段程式叫起來跑**，再跟後端的答案逐筆對。沒有 node 的話它會退回比對舊的存檔答案——**還是會顯示 PASS，但其實沒驗到前端**。所以最好裝。

### Step 0.2：進資料夾、裝東西

```bash
cd ~/claude-new-course/agent_group_projects/cv-self-evolving-console
uv sync --extra train
```

⏱ **第一次跑**要下載約 1.1GB（含 torch / ultralytics），視網路速度要幾分鐘，**這是正常的**。
**第二次之後**才會是 2 秒左右。

⚠️ **`--extra train` 從這一步開始就不能省，後面每一條 `uv run` 都要帶。**
`uv run`（不帶 extra）會把環境同步回「沒有 train extra」的狀態 —— 實測 `uv sync --dry-run`
回「Would uninstall 33 packages」，torch / ultralytics / matplotlib 全部被反安裝。
講師最容易踩的坑就是這個：照舊講稿起 server，s01–s04 一切正常，**s05 突然紅燈**。

💡 **torch 是 optional extra 不是基礎依賴**：打開 `pyproject.toml` 看 `dependencies` 只有那六個
（fastapi、uvicorn、numpy、pillow、scipy、scikit-learn），torch 在 `[project.optional-dependencies].train`。

### Step 0.3：產生 120 張假晶圓照片

```bash
uv run --extra train python scripts/gen_demo_wafers.py
```

輸出大概長這樣（還會多幾行路徑資訊，正常）：

```
PNG             120 張 · 256×256 RGB · seed 42
型態分佈        {'scratch': 30, 'particle': 30, 'ring': 30, 'edge-loss': 30}
GT bbox         155 個 · 平均 1.29 個/張
```

💡 **為什麼用假照片？** 因為它是程式畫的，所以程式**知道正確答案在哪**（那 155 個框）。等一下的考卷就是拿「自動畫的框」去對「正確答案」。真實照片沒有這個好處。

### Step 0.4：跑考卷

```bash
uv run --extra train python scripts/selfcheck.py
```

應該看到：

```
[PASS] A 事件重播一致（完整讀 == ?since= 續讀）
[PASS] B 抽樣一致（Python == 前端 stratifiedSplit）
       node 現跑 index.html 抽出的 stratifiedSplit · fixture 40 筆逐筆相同 ...
[PASS] C auto-bbox IoU 中位數 >= 0.6 且框數 <= GT×1.2
3/3 PASS · 1.3 秒
```

**三條全 PASS 才算沒壞。**

⚠️ 特別看 **B 那行後面**：有沒有寫「node 現跑」？如果寫的是「node 不可用，退回比對黃金值」，代表**這條其實沒真的驗到前端**，回去 Step 0.1 裝 Node.js。

### Step 0.5：開伺服器

```bash
uv run --extra train uvicorn src.app.main:app --reload --reload-dir src
```

⚠️ **`--extra train` 不是裝飾**：它保證 torch / ultralytics 裝得到。少了它，在還沒
`uv sync --extra train` 過的機器上，這台 server 起得來、按鈕按得下去、s01–s04 全綠，
**s05 紅燈**，畫面只寫「結束時狀態是 crashed」。
（更正：裸 `uv run` **不會**把已經裝好的 torch 拆掉 —— uv 0.12.7 預設 inexact，2026-09-12 實測過。
會拆掉的是不帶 extra 的 `uv sync`。）（真因 `ModuleNotFoundError: No module named 'ultralytics'` 現在會被讀出來接在
錯誤訊息後面，但最省事的做法是一開始就帶對。）

⚠️ **伺服器會一直佔住這個終端機**，游標不會回來——**這是正常的**。

- **要下別的指令，請開第二個終端機分頁**（Mac：`Cmd + T`），然後 `cd` 到同一個資料夾
- 真的要停伺服器按 `Ctrl + C`，但停了網頁就打不開了

瀏覽器開 **http://127.0.0.1:8000/**

### Step 0.6：按那顆按鈕

左邊選 `preset = teaching`，然後按 **「開始 run（s01 → s08 一條龍）」**。

⚠️ **不要去按右欄那顆「開始訓練（一條龍自動跑 s05→s07）」** ——訓練由這條龍自己跑，
那顆是給單獨重跑用的（現在是灰的）。畫面上有四顆灰的是刻意鎖住的（M6 的入口）。

你會看到（**這 5 分鐘台上要講的東西**）：

- 0:00–0:15　縮圖**一張一張**跳出來（s01）
- 0:15–0:30　每張圖上**慢慢長出紅框**（s03），最後一行 `auto-bbox vs 合成 GT：IoU 中位數 1.000`
- 0:30–0:45　六張 montage 拼好，rail 下面出現「呼叫 LLM 命名 6 個群…」（s02 開始）
- **0:45–3:30　整整兩分半只有那一行**：LLM 正在看 montage（實測 150–200 秒，上限 240 秒）。
  頂部預算條這時已經跳成 `LLM 1/24 calls` —— 那就是「它正在燒錢」的證據

- 最後　「量 noise floor：同 config 訓 3 次…約 70 秒」→ 裁決卡與四張圖表自己跳出來（s08）

### Step 1.2：數數看發生了幾件事

（把 `r1` 換成你的編號。`|` 的意思是「把左邊的輸出餵給右邊的程式」）

跑完整的 120 張會看到 **8 種、總共 379 筆**：

```
  120  ds.image         ← 每張圖進來一次
  120  label.mask       ← 每張圖算一次遮罩
```

💡 **重點**：畫面不是「假裝在動」。**畫面上每一個變化，背後都有一行真的事件。** 這是刻意設計的——關掉瀏覽器再打開，畫面可以從這個檔案重建。

### Step 1.3：看「自動畫框」到底是什麼

用文字編輯器打開 `src/autolabel/geometry.py`：

```bash
code src/autolabel/geometry.py       # VS Code
# 或   open -a TextEdit src/autolabel/geometry.py
```

它只做三步：

| 步驟 | 白話 | 程式 |
|---|---|---|
| 1 | 把「有瑕疵的點」挑出來變成黑白圖 | `defect_mask()` |
| 2 | 把太小的雜訊點擦掉 | `despeckle()` |
| 3 | **把黏在一起的點當成同一塊，框起來** | `scipy.ndimage.label()` |

**就這樣。沒有 AI、沒有模型、沒有訓練。**

> **教學金句**：「『AI 自動標註』聽起來很厲害，但這一版連 AI 都沒有——它是國中數學。先用最笨的方法做出能動的東西，再換聰明的，這樣你才知道聰明的有沒有比較好。」

### Step 1.4：為什麼考卷說 IoU 是 1.0000？這是不是太好了？

```
[PASS] C ... IoU 中位數 1.0000 · GT 155 框 / auto 155 框
```

**1.0 看起來很棒，但它其實是「退化值」，不是真本事。**

因為：正確答案（GT）跟自動畫的框，用的是**同一套數學定義**。等於出考卷的人和考試的人是同一個——當然滿分。

真正的考驗要等以後接真實照片、對**人類畫的框**。

> **教學金句**：「看到 1.0000 要先懷疑，不是先開心。分數太漂亮通常代表你在跟自己考試。」

**誠實地把自己的分數標成「這個數字沒有意義」，比衝高分數難多了。**

## Phase 2：故意把它弄壞（15 分鐘）⚠️

**這是整份教材最重要的 15 分鐘。** 你要親眼看到「考卷是真的會抓到錯，不是裝飾」。

### Step 2.1：動一個旋鈕

打開 `src/autolabel/geometry.py`，找到第 39 行左右的：

```python
min_area_px: int = 64
```

（意思是「小於 64 個像素的點就當雜訊丟掉」）

**把 64 改成 16，然後存檔**（`Cmd + S`）。不用重開伺服器。

意思是：本來會被丟掉的小雜點，現在全部留下來當成瑕疵。

### Step 2.2：重跑考卷

```bash
uv run --extra train python scripts/selfcheck.py
```

你會看到 **C 那題變成 FAIL**：

```
[FAIL] C auto-bbox IoU 中位數 >= 0.6 且框數 <= GT×1.2
       IoU 中位數 1.0000 ... GT 155 框 / auto 942 框（6.08× > 上限 1.2×）
```

### Step 2.3：看懂這一題在考什麼

注意看：**IoU 還是 1.0000，還是「滿分」。** 但框數從 155 爆到 942——多畫了 787 個不存在的瑕疵。

**如果考卷只考 IoU，這個錯會全綠通過。**

這正是這個專案在對抗審查時被抓到的真實問題。原本的考卷只看 IoU，後來補上「框數不能超過正確答案的 1.2 倍」才抓得到。

> **教學金句**：「一張永遠不會當人的考卷，不是考卷，是裝飾品。每寫一條檢查，先問自己：什麼情況下它會 FAIL？答不出來就是假的。」

### Step 2.4：改回來

把 `min_area_px` 改回 `64`，存檔，重跑確認 **3/3 PASS**。

## Phase 2.5：換成真的晶圓照片（15 分鐘）🛰

左欄的 `source` 從 `demo` 換成 `roboflow`，同一顆按鈕會去抓
**WM-811K 真實晶圓瑕疵資料集**（409 張，每一張都有人工畫好的 bbox）。

### Step 2.5.5：真實資料的天花板（這一段是重點）

跑完 s03，右上角「標註天花板」那塊會是**灰色**的，寫著「退化值」。
那是 demo 的合成 GT。換成真人工框之後，去問後端真正的天花板：

```bash

```

| 資料 | 正確答案哪來 | auto-bbox 的 IoU 中位數 |
|---|---|---|
| demo（合成） | 程式生成，跟 auto-bbox **同一套連通分量定義** | **1.0000** ← 退化值，沒有意義 |
| Roboflow（真實） | **人類畫的框** | **0.6381**（95% CI 0.6035–0.6783） |

對照 noise floor（同一組設定重跑三次的隨機抖動）2σ = 0.1479 —— **雜訊佔了整個可達區間的 44%**。

> **教學金句**：「天花板 0.64 的意思是：就算模型完美複製了 auto-label，也就這樣了。
> 這種時候再調參數是在調一個上限 0.34 的東西，處方是**去修 auto-label 或補人工框**，不是換模型。」

**這就是為什麼 Step 1.4 要你『看到 1.0000 先懷疑』。** 同一套程式、同一顆按鈕，

### Step 2.5.6：一個還沒解決的坑（誠實揭露）

Roboflow 那份資料自帶人工類別（`nc:1`、`names:['Donut']`），
但這個專案的 🔒 class 真相表 schema 是照「KMeans 分群 + LLM 命名」凍結的：
`nc` 必須在 3..6、名字只能從六個固定詞挑。**真實資料集三條全踩。**

所以按鈕走的是 `labels:"auto"`（真圖 + 機器自己生框，s01→s08 跑得完）。
要用人工框當 GT 得明講：

```bash
curl -s -X POST localhost:8000/api/v1/runs -H 'content-type: application/json' \
  -d '{"mode":"oneshot","source":"roboflow","labels":"human","limit":409}'
```

它會在 **s02 停下來**回 `409 CLASS_TABLE_SCHEMA_CONFLICT`。**這是刻意的**：
補到 3 類等於發明類別，讓 KMeans 當類別體系而框留人工則是框的類別會靜默錯位。

> **教學金句**：「契約擋住你的時候，正確的動作是走變更流程，不是把資料硬塞進舊欄位。
> 硬塞的那一刻不會有任何錯誤訊息 —— 那才是最貴的那種 bug。」

## Phase 3：這台東西是怎麼被 AI 蓋出來的 ⭐（30 分鐘）🧠

**前面都是「用」，這一段是「做」。你要學的是怎麼指揮 AI。**

我（Claude）蓋這個專案時走了六步。每一步都可以照抄。

### Step 3.1：不要拿 AI 的第一個答案

❌ **新手最常見的做法**：

```
幫我設計一個 CV 自動訓練系統，要有幾個 agent
```

AI 會給你一個看起來很像樣的答案。**問題是你不知道它好不好，因為你沒有第二個可以比。**

✅ **我實際做的**：叫 AI 用**四種完全不同的切法**各設計一份，再互相評審。

| 切法 | 怎麼分工 |
|---|---|
| A 按流程階段 | 資料一位、標註一位、訓練一位、評估一位 |
| B 按困難決策 | 每個「需要研究、有對錯」的判斷一位 |
| C 按 API 邊界 | 先看前端需要什麼，反推後端要幾個窗口 |
| D 按失效模式 | 按「真實專案是怎麼死的」來分 |

然後每一份用兩個角度評審（各五項、每項 10 分，**滿分 50**）：**「做得出來嗎」**和**「講得動嗎、有沒有人多到變表演」**。

結果：B 最高（28.5）、A 第二（28）、C 26.5、D 26。**分數都不高，而且很接近——代表四份都有明顯缺點，沒有一份可以直接用。**

所以最後定案是：**用 B 當骨架，把 A、C、D 各自最好的點搬進去。**

> **教學金句**：「一個答案你只能接受或不接受；四個答案你才能挑。而且要讓 AI 自己互相挑毛病，它挑自己的比你挑還狠。」

### Step 3.2：把定案寫成檔案，不要留在對話裡

聊天記錄會消失、會被截斷、新開一個視窗就沒了。

所以定案立刻寫成 `_Context/DESIGN.md`（772 行）。之後每一個 agent 開工的第一件事都是「先讀這份」。

> **教學金句**：「AI 的記憶不在對話裡，在檔案裡。你想讓它下禮拜還記得，就寫成檔案。」

### Step 3.3：先凍結「接口」，再讓大家平行做

想像兩個人各做一半：一個做畫面、一個做後端。如果沒先講好**資料長什麼樣**，兩邊做完一定接不起來。

所以有 **M0 契約閘門**：先寫死

- 每一則事件長什麼樣（欄位名、型別）
- 有哪些窗口（API）、各回什麼
- 斷線之後怎麼接回來

`_Context/api-contract.md` 就是這份，標了 🔒 代表**要改要批准**。

**契約沒凍結之前，不准任何人開工。**

### Step 3.4：分工要讓「球員不能兼裁判」

這是整個設計最重要的一句話，而且不是技術問題，是**人性問題**。

| 角色 | 負責 | 為什麼不能兼別的 |
|---|---|---|
| 資料專家 | 做出「正確答案」 | 如果他同時打分數，他會把正確答案調成剛好能過 |
| 訓練專家 | 訓練模型 | 如果他同時打分數，他會挑分數最高的那一刻收手 |
| 評分專家 | **只有他能說「這算不算進步」** | 他不准提任何建議，因為有立場就會偏心 |
| 裁決專家 | 決定這輪只改哪一個東西、什麼時候停 | 他不碰任何技術參數，不然會偏袒自己的 |
| 主控台 | 畫面 + 記錄 | **他刻意不懂 CV**，所以他的「你說的跟你做的不一樣」指控才可信 |

> **教學金句**：「自己出考卷、自己考試、自己改考卷——這樣得到的 100 分，你自己也不敢信。AI 也一樣。」

### Step 3.5：每一步都要留一個「會失敗的檢查」

Phase 2 你已經玩過了。規則很簡單：

**寫完一段有邏輯的程式，就留一個「壞掉時會變紅」的檢查。**

不用學測試框架。這個專案的檢查就是：

- `scripts/selfcheck.py` — 三條
- 瀏覽器打開 **http://127.0.0.1:8000/?selftest=1** — 18 條

試試看那個網址，你會看到「全部通過（18 條）」。

### Step 3.6：讓 AI 審查 AI 寫的東西

程式寫完後，我叫**三個新的 AI** 用三個角度去挑毛病，而且明講「**預設懷疑，不要欣賞**」：

| 角度 | 找什麼 |
|---|---|
| 護欄與正確性 | 該擋的有沒有真的擋住 |
| 契約一致性 | 前端跟後端對不對得上 |
| 可教學與精簡 | 有沒有寫了用不到的東西、新手看不看得懂 |

**它們抓到一個很嚴重的錯**，而且是原本的驗收完全看不到的：

> 圖片是正方形（256×256），但畫面上的框是塞在一個 4:3 的格子裡。
> 結果**每個框畫出來只有正確高度的 0.75 倍**，而且會往下偏。
> 但當時的驗收只「數框的數量」（155 個，對的），**一個框的位置都沒量過**，所以全綠通過。

最毒的地方：右邊寫著「IoU 1.0000 PASS」，畫面上的框卻裝不下瑕疵。學生會學到「原來 IoU 1.0 長這樣」。

修法只有一行 CSS（`aspect-ratio: 4/3` → `1`），但**沒有人去審就永遠不會被發現**。

> **教學金句**：「AI 說『我做好了，測試都過了』的時候，要問的是『你的測試會不會因為這個錯而變紅？』——常常不會。」

### Step 3.7：連這份教材也要找人審——而且審出我寫錯

寫完這份 walkthrough，我又叫三個 AI 分別扮演**高中生**、**照打不腦補的工程師**、**助教**去讀。

結果它們抓出我寫錯的事實，包括：

| 我原本寫的 | 實際 |
|---|---|
| 11 格裡「3 格會亮」 | **2 格**，而且不連續（第 2 格是灰的） |
| teaching 24 張「15.2 秒」 | **6.0 秒**（我當時量到自己的等待時間裡去了） |
| 「非本機一律 403」 | 護欄只擋 API，網頁本身誰都打得開 |
| 「沒裝 node 考卷會 FAIL」 | **仍會 PASS**，只是偷偷退回比對舊答案 |

> **教學金句**：「連『我親自驗過』都可能是錯的——因為你可能量錯了東西。找不同立場的人重量一次，比你自己再看三遍有用。」

### Step 3.8（真實踩坑）：我自己也翻車過

最後一步「修正」那個 AI **連續失敗六次**，一個字都吐不出來。

原因：我把三份審查報告 + 驗收報告全部塞進同一個指令，變成 **205KB** 的巨大 prompt，它第一步就卡死。

修法：**不要把所有東西塞給一個 AI。** 拆小。

> **教學金句**：「AI 卡住，八成不是它笨，是你一次給太多。指令跟便當一樣，給太多它會噎到。」

| 縮圖瞬間全部長完 | `preset` 選成 `real` 了 | 改成 `teaching` |
| 按了按鈕，畫面像沒反應 | **一次只准跑一個 run**。錯誤橫幅現在在 stage 燈那一排底下、整列寬、14px | 看那條紅橫幅。按「中止 run」，或用下面那條指令清掉卡住的 run |
| 選了 roboflow，按鈕按下去卡了 4 秒才有反應 | **正常**：第一次要下載 8.8 MB 的 zip，而且刻意等它下載完才回應（失敗才能當場回錯誤，不會留下一條紅色的鬼 run） | 第二次是 0 秒（沿用 `01-raw-data/roboflow/`） |
| `ROBOFLOW_KEY_MISSING` | `.env` 沒有 `ROBOFLOW_API_KEY` | 照橫幅上寫的做：`cp .env.example .env` 填 key，**重開 server**（`.env` 是啟動時讀的） |
| `ROBOFLOW_KEY_INVALID` | 複製到 Publishable Key，或 key 打錯 | 回 Settings → Roboflow API 拿 **Private** API Key |
| roboflow 的 run 在 s02 紅燈、`CLASS_TABLE_SCHEMA_CONFLICT` | 你用了 `labels:"human"`。🔒 class 表 schema 是照 KMeans 命名凍的（nc 3..6 + 固定詞彙），真實資料集的 `nc:1 names:['Donut']` 塞不進去 | 前端那顆按鈕走的是 `labels:"auto"`，不會踩到。細節看 Phase 2.5.6 |
| 上一個 run 當掉了，狀態卡在 running，按鈕永遠是死的 | 舊版才會。現在 server 一重啟就會把孤兒子行程殺掉並把那個 run 標成 `crashed` | 還是卡住的話 `curl -s -X POST localhost:8000/api/v1/runs/rNN/cancel`（`rNN` 是紅字裡那個編號） |
| `runs/r1/` 裡的數字跟文件對不上 | `r1` 不一定是你跑的那個 | `ls runs/` 看**數字最大**的那個 |
| 用區網 IP（例如 192.168.x.x）連 | 網頁打得開但功能全壞——Host 護欄只擋 `/api/v1`，不擋網頁本身 | **一律用 `127.0.0.1` 或 `localhost`**。這個服務不可部署到公開網址 |
| 期待它訓練但沒有 | 訓練在 s07，前面四段要先跑完（約 4 分鐘） | 看 rail 的第 7 格與 `04-experiments/<train_id>/train.log` |
| 改了 `geometry.py` 之後 IoU 還是 1.0 但總覺得怪 | IoU 看不出「框數爆炸」 | 看框數那一欄，不要只看 IoU |

💡 **關於 `--reload-dir src`**：加它是為了**讓檔案監看器不要去掃 `.venv` 和幾千張 PNG**（會變慢）。
網路上常見的說法「不加就會每寫一筆事件重啟」是**錯的**——uvicorn 預設只監看 `*.py`，`.jsonl` 不會觸發重啟（實測寫入 379 筆事件，重啟 0 次）。

**故意踩的兩個坑**

1. **先只講 IoU 1.0000，讓學生覺得「好強」** → 再問「為什麼出考卷和考試的是同一個人？」→ 臉色會變。比直接講「這是退化值」有效十倍。
2. **Phase 2 一定要親手做**，不要用投影片帶過。看到綠變紅的那一刻是整堂課的高潮。

**給不同程度的人**

| 對象 | 重點放哪 | 可以跳過 |
|---|---|---|
| 高中生 / 完全新手 | 名詞對照表 + Phase 0–2 + train/valid/test 比喻 | Phase 3.3 契約那段 |
| 大學生 / 會寫程式 | Phase 2 + Phase 3 全部 | 名詞對照表 |
| 已經在做 ML 的人 | Phase 3.4 分權 + 3.6 對抗審查 | Phase 0–1 |
| 主管 / 非技術 | 開場那張表 + Phase 3.1 + 3.6 那個 blocker 的故事 | 其他全部 |

## 一句話總結

> **不要相信 AI 的第一個答案（叫它出四個再互評），不要相信它說「我做好了」（叫它證明給你看，還要叫別的 AI 去挑毛病），也不要相信漂亮的分數（先問「是不是自己跟自己考試」）——連你自己親手量的數字都要有人重量一次。**
